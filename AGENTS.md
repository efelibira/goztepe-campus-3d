# Agent instructions for goztepe-campus-3d

- This is a standalone application. Never import source files at runtime from `goztepe-campus-map`; use only this project's local data copies.
- Do not modify the separate `goztepe-campus-map` repository or its branches as part of work in this project.
- Preserve OSM feature IDs (`way/...` and `relation/...`) as building IDs. Normalize the `osm:` prefix only when looking up source overrides.
- Keep source GeoJSON immutable. `public/data/building-visual-overrides.json` is the baseline presentation source; user changes to source buildings belong in the scene document's `buildingOverrides` map, keyed by OSM ID. Never turn source buildings into user-placed objects.
- Keep source building overrides and user-placed objects as separate groups in the versioned persisted scene document. Use `src/editor/sceneDocument.js` for validation/import/export and `src/editor/sceneStore.js` for centralized mutations, autosave, and undo/redo. Version 1 is readable and upgrades to version 2; update the v2 schema and keep the v1 schema for compatibility.
- Register new procedural object types in `src/editor/objectCatalog.js` and add an independent model component to `src/components/ObjectModels.tsx`. Saved records reference models by `objectType` and `variant`; they must not contain Three.js objects or React component references.
- Keep placed object transform vectors in local scene meters with Three.js Y as elevation. Persist model-specific settings under the object's `properties` record.
- Update the current `public/schemas/scene-document.v2.schema.json` and add tests when changing the saved document shape. Preserve older schemas and explicit upgrade paths; do not silently reinterpret old records.
- Building GLB assignments are optional building overrides. Keep OSM identity, name/unit resolution, and source footprint independent from the visual model. Missing or failed GLB assets must fall back to generated GeoJSON massing. Preserve materials embedded in GLB files and use `BLENDER_MODELING.md` for scale/origin conventions.
- Keep `public/models/catalog.json` as the single validated catalog of GLB IDs, display names, and paths relative to `public/models/`. Building overrides and placed GLB records store catalog IDs, never binary data or arbitrary URLs. Placed GLB instances use `objectType: "glb-model"`, `variant: <assetId>`, a UUID record ID, and `properties.name`. Keep catalog paths inside `public/models/` and preserve Drei `useGLTF` URL caching/shared geometry and material references.
- When changing the catalog contract, update `public/schemas/model-catalog.v1.schema.json` and catalog validation tests together.
- Keep placed GLB objects in the existing objects group; do not create a second persistence/store system. Missing catalog entries or load failures must remain recoverable and show a safe fallback.
- Treat localStorage and imported JSON as untrusted input. Validate before mutation and make corrupt saved data recoverable without modifying source data.
- Keep normal building inspection separate from edit mode. In edit mode provide Camera and Object control modes. In Object mode leave OrbitControls left-drag unmapped except while Option is held; in Camera mode map left-drag to rotate. Keep right-drag mapped to pan and wheel/trackpad zoom enabled in both modes.
- Selection must remain available in Camera mode, while TransformControls must be absent there. Disable OrbitControls only while TransformControls is actively dragging; placement clicks must not conflict with camera gestures.
- Do not clear the selected object from Canvas/group `onPointerMissed` while a TransformControls drag is active; the gizmo's native raycast is separate from React Three Fiber's pointer target graph. Ground and walkway meshes should remain non-interactive outside placement.
- Track Option from keyboard and pointer state, and clear it on blur/hidden-page transitions. A single TransformControls drag must remain one store transaction/undo step.
- Keep the selected object's numeric position, rotation, and scale controls bound to the saved transform. Convert rotation UI degrees to stored radians; validate finite values, minimum scale, and non-negative Y before a one-field store transaction.
- Keep placed object model origins on the campus ground plane; constrain translation above ground and preserve the scene store as the only source of saved transforms.
- In edit mode, keep keyboard shortcuts focused and modifier-safe: `1`–`4` arm catalog placement, `Escape` closes placement, `D` duplicates the selected placed object, `Z` undoes, `Y` redoes, and the existing `Backspace` deletion remains. Ignore shortcuts in text/numeric inputs and while Cmd, Ctrl, Option, or Shift is held. Placement remains armed after a placement click.
- Display numeric transform values with two decimal places while preserving the saved JSON values and rotation-radian storage.
- Direct dragging is a shared placed-object renderer behavior, never a per-model behavior. Use a horizontal raycast plane, preserve pointer-to-origin X/Z offset and starting Y, reject proposed positions outside the projected campus Polygon/MultiPolygon (including holes), and commit one store transaction after the thresholded drag finishes. Keep temporary pointer movement out of undo history.
- Release pointer capture and clean up pointerup, pointercancel, blur, and unmount paths. Direct body dragging must be limited to Object edit mode without Option or placement armed, and must yield to TransformControls handles.
- `displayHeight` is not always measured. Preserve and display its `heightSource`; `placeholder` values are estimates. OSM floor-count conversions are estimates too.
- Convert WGS84 coordinates through `src/data/projectCoordinates.js`; keep Y as elevation and the campus footprint on the X/Z plane.
- Polygon interior rings represent holes. Do not drop them when generating `Shape`/`ExtrudeGeometry`; handle every polygon in MultiPolygon features.
- Keep the first-person walking mode and edit/placement mode separate so camera and pointer controls do not fight each other.
- Preserve data attribution in `DATA_SOURCES.md` and the application interface. Re-check source licensing before publishing altered or redistributed source data.
- Avoid adding dependencies until a concrete feature needs them. Keep README and this file updated when the architecture changes.

- GLB disk imports belong only to `server/modelImportPlugin.ts` via Vite `configureServer`. Never expose the write API over LAN, add it to production/preview, relax same-origin/loopback checks, or use request filenames as paths. Keep 50 MiB limits on both sides and validate with `src/data/glbImport.ts` before writing.
- Preserve catalog entries and model IDs. New imports use exclusive UUID filenames under `public/models/imported/`, a catalog lock and atomic catalog replacement. Reject symlinked storage directories and invalid existing catalogs; never silently repair/delete unknown records.
- Keep import UI separate from sceneStore: import refreshes the shared catalog for both building assignment and placement; scene undo/redo and JSON remain unchanged. Test uploads with generated fixtures and temporary directories; never overwrite user models or localStorage for tests.
- Read `AI_HANDOFF.md` for the current GLB library state and verification limits before continuing work with another AI tool. Keep it aligned with the catalog, importer, and scene contracts when those change.
